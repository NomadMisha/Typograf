# Типограф

Учебный помощник редактора: локальная проверка орфографии, правила пунктуации и неразрывные пробелы, просмотр и подтверждение правок.

[История изменений проекта](CHANGELOG.md).

## Безопасность языковых исправлений

Автоматически исправляются проверенные опечатки и отдельные локальные правила. Единственная словарная или онлайн-подсказка для неизвестного слова теперь требует подтверждения: похожее написание не устанавливает смысл. Например, для «Крипис» предлагаются «Крепись» и «Кризис». Финальную точку тоже можно выбрать вручную, чтобы не дописывать её к заголовкам. Регистр слов, адреса почты, идентификаторы и технические имена файлов защищены.

Результаты сравнения до и после, происхождение наборов и оставшиеся ошибки описаны в [аудите корректуры](outputs/typograf-prototype/SAFETY_AUDIT.md). 50 примеров использовались для настройки; 16 дополнительных — для отложенной диагностики. Оба набора составлены ИИ и не проверены редактором. Они не заменяют независимую оценку качества на реальных черновиках.

Из корня репозитория:

```sh
node work/spell-build/evaluate-safety.mjs --html docs/index.html --require-clean
node work/spell-build/evaluate-safety.mjs --dataset work/spell-build/safety-holdout.json --html docs/index.html
```

Из `work/spell-build` команда `node test-evaluation.mjs` проверяет, что постороннее предупреждение не засчитывается как обнаружение другой ошибки. Для редакторских эталонов в `gold-cases.json` можно указать `expectedIssues` с точными исходными фрагментами `before` и русскими категориями `category`; без такой разметки обнаружением считается только полное совпадение исправленного текста с эталоном.

## Документы и JSON

На экране результата нажмите **«В историю»**, чтобы сохранить проверку. Подтверждение результата тоже сохраняет его в истории. Блок **«Мои документы»** позволяет открыть прошлый результат, продолжить редактирование или удалить запись после подтверждения. Каждый новый запуск проверки создаёт отдельную запись при сохранении; повторное сохранение открытого результата обновляет его запись.

История хранится в `localStorage` этого браузера для пути сайта. Адреса `/Typograf/` и `/Typograf/index.html` используют одну историю. Сохранённые результаты содержат исходник, исправленный текст, замечания, решения редактора, подсветку, даты и статус. Редактируемый черновик тоже можно сохранить кнопкой «В историю».

**«Скачать JSON»** выгружает все документы и личный словарь в файл. **«Загрузить JSON»** добавляет документы с новыми идентификаторами и объединяет словарь; существующие документы не перезаписываются. Структура проверяется до применения изменений. Чужой JSON не включает онлайн-проверку и не запускает сетевые запросы. Текущий текст не заменяется при импорте; открытие документа требует подтверждения, если в редакторе уже есть текст или результат.

Личный словарь хранит отдельные слова и учитывается при следующей проверке орфографии. Он не отключает грамматические правила.

Лимиты: 100 документов, до 200 000 символов в каждом исходнике/результате/черновике, 2 000 слов в личном словаре, 1,5 млн символов компактного JSON для всей истории. Импорт: до 8 МБ и 6 млн символов входного JSON. При заполнении истории удалите ненужные записи после экспорта. При запрете хранилища или исчерпании браузерной квоты новые данные остаются только в памяти вкладки; интерфейс сообщает об этом, и их можно скачать. Некорректная сохранённая история не перезаписывается автоматически.

Очистка данных браузера удалит историю, поэтому храните резервные JSON-копии. JSON содержит тексты статей: не добавляйте личные выгрузки в GitHub. Их стандартные имена исключены в `.gitignore`.

Это файловый формат данных с браузерным хранилищем, а не SQL-СУБД или общий сервер нескольких пользователей. Для преподавателя подготовлены [описание структуры JSON Schema](work/spell-build/history.schema.json) и [пример с вымышленным текстом](examples/history-example.json).

## Публикация на GitHub Pages

Готовая автономная страница — `docs/index.html`. Словарь, JavaScript, стили и лицензии включены в HTML. Файл `docs/.nojekyll` отключает обработку Jekyll. Навигация использует относительные ссылки и работает в подпапке репозитория `Typograf`.

В [настройках Pages](https://github.com/NomadMisha/Typograf/settings/pages) выберите:

1. **Source:** Deploy from a branch.
2. **Branch:** `main`, папка **`/docs`**.
3. Нажмите **Save** и дождитесь завершения публикации.

Адрес сайта: <https://nomadmisha.github.io/Typograf/>.

## Обновление опубликованной версии

После обновления однофайловой версии выполните из корня репозитория (Node.js 20+):

```sh
node work/spell-build/build-pages.mjs
```

Скрипт обновляет только `docs/index.html` и `.nojekyll`. Результат нужно закоммитить и отправить в `main`. Исходники сохраняются в `outputs/typograf-prototype`, однофайловая версия — в `outputs/typograf-single-file-v20`, код сборки — в `work/spell-build`.

## Проверка на статическом хостинге

По умолчанию проверка выполняется в браузере; локальный Node.js-сервис для сайта не нужен. Если пользователь включит онлайн-проверку, страница обращается напрямую к Яндекс.Спеллеру и публичному API LanguageTool. GitHub Pages не запускает `work/typograf-service` и не предоставляет маршруты `/api/spelling` и `/api/grammar`.

Онлайн-проверка зависит от доступности, CORS и ограничений внешних API; при ошибке сервисов сайт показывает предупреждение и локальные правки. Конфиденциальные тексты не следует отправлять во внешние сервисы. Для полноценного сервера и собственного LanguageTool см. [инструкцию локального сервиса](work/typograf-service/README.md).

Регрессионные проверки опубликованного HTML:

```sh
cd work/spell-build
TYPOGRAF_HTML=../../docs/index.html node test-app.mjs
cd ../typograf-service
TYPOGRAF_HTML=../../docs/index.html TYPOGRAF_STATIC=1 node test-frontend-mode.mjs
```
