# Типограф

Учебный помощник редактора: локальная проверка орфографии, правила пунктуации и неразрывные пробелы, просмотр и подтверждение правок.

[История изменений проекта](CHANGELOG.md).

## Безопасность языковых исправлений

Автоматически исправляются известные опечатки, несколько узких грамматических конструкций и типографика: лишние пробелы, парные кавычки, тире между словами, числовые интервалы с единицами, неразрывные пробелы. Код, JSON-фрагменты, ссылки, почта и технические имена файлов защищены.

Контекстная пунктуация, в том числе предложения LanguageTool, требует выбора редактора. Единственная словарная или онлайн-подсказка для неизвестного слова тоже требует подтверждения: похожее написание не устанавливает смысл. Например, для «Крипис» предлагаются «Крепись» и «Кризис». Финальную точку можно выбрать вручную, чтобы не дописывать её к заголовкам. Смешение кириллицы и латиницы отмечается без автоматической транслитерации.

## Работа редактора

1. Откройте [браузерную версию](https://nomadmisha.github.io/Typograf/) или запустите локальный сервис по [инструкции](work/typograf-service/README.md).
2. Вставьте черновик и нажмите «Проверить текст». Онлайн-переключатель по умолчанию выключен. Его включение разрешает отправку текста внешним сервисам; для конфиденциальной статьи оставьте его выключенным.
3. Прочитайте готовый текст и замечания. Номера связывают список с фрагментами текста. Выбирайте подходящие варианты; ошибочное замечание можно отклонить. Применение соседних правок сохраняет другие предложения и положение списка.
4. При необходимости отредактируйте результат и повторите проверку. «Подтвердить результат» после модального подтверждения возвращает выбранный текст в поле на главном экране и сохраняет историю. Подтверждение означает решение редактора, а не сертификат безошибочности.
5. Кнопка с двумя квадратами копирует чистый текст без подсветки и номеров. «Скачать JSON» создаёт резервную копию истории и словаря.

## Проверка качества

[Отчёт от 15 октября](outputs/typograf-prototype/BROWSER_QUALITY_REPORT.md): 97 сценариев приложения, отдельные проверки измерения качества и сервиса. В зафиксированном наборе из 40 коротких фрагментов MDN обнаружено 40 внесённых ошибок, правильный вариант доступен для 38; исходные тексты автоматически не изменились. Это ограниченная диагностика с разметкой ИИ, не оценка качества любой статьи.

Для настоящей редакторской оценки подготовлена [форма проверки примеров](docs/editorial-review.html). В ней ничего не подтверждено заранее. Редактор проверяет контекст по ссылке, исправляет эталон, отмечает карточку и указывает подпись; экспортируются только явно подтверждённые карточки. JSON не отправляется автоматически. [Источники и лицензия MDN](work/spell-build/TECHNICAL_CORPUS_LICENSE.md).

Скачанный `gold-cases-reviewed.json` — набор эталонов для тестирования, не файл истории приложения. Проверьте его командой из `work/spell-build`:

```sh
node evaluate-gold.mjs /путь/к/gold-cases-reviewed.json
```

После проверки и согласования этот файл можно использовать как `work/spell-build/gold-cases.json`. Текущий редакторский набор пуст; критерий пилота требует минимум 100 проверенных примеров. Форма MDN даёт до 80 примеров, поэтому потребуются и дополнительные черновики. Подпись в JSON не удостоверяет личность проверяющего.

Локальные проверки (Node.js 20+, из `work/spell-build`):

```sh
node build-pages.mjs
TYPOGRAF_HTML=../../docs/index.html node test-app.mjs
node test-evaluation.mjs
TYPOGRAF_HTML=../../docs/index.html node quality-gate.mjs
node deep-qa.mjs
```

`quality-gate.mjs` завершится с ошибкой при изменении исходных контролей или ухудшении обнаружения по сравнению с зафиксированным состоянием. `--pilot` дополнительно требует редакторский набор. Workflow [Test and deploy Pages](.github/workflows/check.yml) запускается на каждый push в `main`, для pull request и вручную. Он собирает `docs/`, запускает `test-app.mjs` и `quality-gate.mjs`, затем дополнительные проверки оценивания и сервиса. Только успешное задание проверок разрешает загрузку сборки и отдельное задание публикации. Даже при падении `test-app.mjs` проверка качества запускается, если сборка прошла.

При ошибке текущий опубликованный сайт сохраняется. В [GitHub Actions](https://github.com/NomadMisha/Typograf/actions/workflows/check.yml) откройте красный запуск: причина показана в шагах и разделе Summary, последние строки логов — в отчёте, полные логи проверок — в артефакте `check-failure-*` (хранятся 7 дней). Workflow собирает файлы в `docs/` на временном runner и не делает автоматических коммитов в репозиторий.

Результаты сравнения до и после, происхождение наборов и оставшиеся ошибки описаны в [аудите корректуры](outputs/typograf-prototype/SAFETY_AUDIT.md). 50 примеров использовались для настройки; 16 дополнительных — для отложенной диагностики. Оба набора составлены ИИ и не проверены редактором. Они не заменяют независимую оценку качества на реальных черновиках.

Из корня репозитория:

```sh
node work/spell-build/evaluate-safety.mjs --html docs/index.html --require-clean
node work/spell-build/evaluate-safety.mjs --dataset work/spell-build/safety-holdout.json --html docs/index.html
```

Из `work/spell-build` команда `node test-evaluation.mjs` проверяет, что постороннее предупреждение не засчитывается как обнаружение другой ошибки. Для редакторских эталонов в `gold-cases.json` можно указать `expectedIssues` с точными исходными фрагментами `before` и русскими категориями `category`; без такой разметки обнаружением считается полное совпадение исправленного текста с эталоном либо точный ручной вариант, который восстанавливает весь эталонный текст.

## Документы и JSON

На экране результата нажмите **«В историю»**, чтобы сохранить проверку. Подтверждение результата тоже сохраняет его в истории. Блок **«Мои документы»** позволяет открыть прошлый результат, продолжить редактирование или удалить запись после подтверждения. Каждый новый запуск проверки создаёт отдельную запись при сохранении; повторное сохранение открытого результата обновляет его запись.

История хранится в `localStorage` этого браузера для пути сайта. Адреса `/Typograf/` и `/Typograf/index.html` используют одну историю. Сохранённые результаты содержат исходник, исправленный текст, замечания, решения редактора, подсветку, даты и статус. Редактируемый черновик тоже можно сохранить кнопкой «В историю».

**«Скачать JSON»** выгружает все документы и личный словарь в файл. **«Загрузить JSON»** добавляет документы с новыми идентификаторами и объединяет словарь; существующие документы не перезаписываются. Структура проверяется до применения изменений. Чужой JSON не включает онлайн-проверку и не запускает сетевые запросы. Текущий текст не заменяется при импорте; открытие документа требует подтверждения, если в редакторе уже есть текст или результат.

Личный словарь хранит отдельные слова и учитывается при следующей проверке орфографии. Он не отключает грамматические правила.

Лимиты: 100 документов, до 200 000 символов в каждом исходнике/результате/черновике, 2 000 слов в личном словаре, 1,5 млн символов компактного JSON для всей истории. Импорт: до 8 МБ и 6 млн символов входного JSON. При заполнении истории удалите ненужные записи после экспорта. При запрете хранилища или исчерпании браузерной квоты новые данные остаются только в памяти вкладки; интерфейс сообщает об этом, и их можно скачать. Некорректная сохранённая история не перезаписывается автоматически.

Очистка данных браузера удалит историю, поэтому храните резервные JSON-копии. JSON содержит тексты статей: не добавляйте личные выгрузки в GitHub. Их стандартные имена исключены в `.gitignore`.

Это файловый формат данных с браузерным хранилищем, а не SQL-СУБД или общий сервер нескольких пользователей. Для преподавателя подготовлены [описание структуры JSON Schema](work/spell-build/history.schema.json) и [пример с вымышленным текстом](examples/history-example.json).

## Публикация на GitHub Pages

Готовая автономная страница — `docs/index.html`. Словарь, JavaScript, стили и лицензии включены в HTML. Файл `docs/.nojekyll` отключает обработку Jekyll. Навигация использует относительные ссылки и работает в подпапке репозитория `Typograf`.

В [настройках Pages](https://github.com/NomadMisha/Typograf/settings/pages) выберите:

1. **Source:** GitHub Actions.
2. Workflow `.github/workflows/check.yml` собирает папку `docs/` на каждый push в `main`.
3. Публикация выполняется только после успешного завершения проверок. Не включайте параллельную публикацию из ветки: она обходит этот барьер.

Адрес сайта: <https://nomadmisha.github.io/Typograf/>.

## Обновление опубликованной версии

После изменения исходников выполните из `work/spell-build` (Node.js 20+):

```sh
node build-pages.mjs
```

Единственная готовая сборка находится в `docs/`: `index.html`, вспомогательная форма `editorial-review.html` и `.nojekyll`. Команда сразу собирает их из модульных исходников, без промежуточной копии HTML. Результат можно проверить локально и закоммитить вместе с исходниками. После push в `main` GitHub Actions заново собирает и проверяет сайт перед публикацией. Исходники и словарь сохраняются в `outputs/typograf-prototype`, код сборки — в `work/spell-build`.

## Архивы в GitHub Releases

Готовый архив для скачивания размещается только в [GitHub Releases](https://github.com/NomadMisha/Typograf/releases/latest). ZIP не хранится в дереве репозитория. В архиве находится та же сборка, что в `docs/`, и инструкция по запуску; исходники, модели, ключи и пользовательские документы туда не включаются.

После сборки `docs/` создайте архив из корня проекта (Python 3, стандартная библиотека):

```sh
python3 work/spell-build/package-release.py v2026.10.19
```

Команда создаёт `dist/typograf-v2026.10.19.zip` и файл `.zip.sha256`. Папка `dist/` исключена из Git. Для следующего выпуска укажите новый тег. После коммита и push создайте Release для этого коммита и прикрепите ZIP и контрольную сумму. Пользователь распаковывает ZIP и открывает `index.html` в браузере; установка моделей не нужна.

## Проверка на статическом хостинге

По умолчанию проверка выполняется в браузере; локальный Node.js-сервис для сайта не нужен. Если пользователь включит онлайн-проверку, страница обращается напрямую к Яндекс.Спеллеру и публичному API LanguageTool. GitHub Pages не запускает `work/typograf-service` и не предоставляет маршруты `/api/spelling` и `/api/grammar`.

Онлайн-проверка зависит от доступности, CORS и ограничений внешних API; при ошибке сервисов сайт показывает предупреждение и локальные правки. Конфиденциальные тексты не следует отправлять во внешние сервисы. Для полноценного сервера и собственного LanguageTool см. [инструкцию локального сервиса](work/typograf-service/README.md).

Регрессионные проверки опубликованного HTML:

```sh
cd work/spell-build
TYPOGRAF_HTML=../../docs/index.html node test-app.mjs
cd ../typograf-service
TYPOGRAF_HTML=../../docs/index.html TYPOGRAF_STATIC=1 node test-frontend-mode.mjs
```
