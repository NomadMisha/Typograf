# Типограф — учебный прототип

Модульные исходники находятся в `index.html` и `spellcheck.js` (метка «Прототип · 20»). Единственная готовая сборка сайта — `../../docs/index.html`. Архив для передачи преподавателю доступен в [GitHub Releases](https://github.com/NomadMisha/Typograf/releases/latest); распакуйте его и откройте `index.html` в браузере без установки. Для более полноценной онлайн-проверки используйте локальный сервис из `../../work/typograf-service/README.md`.

## История и JSON

Кнопка «В историю» сохраняет текущий результат; подтверждение тоже добавляет его в «Мои документы». История и личный словарь хранятся в браузере. «Скачать JSON» создаёт резервную копию, «Загрузить JSON» объединяет данные без перезаписи существующих документов. При недоступном хранилище скачайте JSON до закрытия вкладки. Это браузерное JSON-хранилище, не SQL-база. Лимиты, схема и пример описаны в [основном README](../../README.md#документы-и-json).

## Как пользоваться

1. Вставьте черновик статьи или нажмите «Попробовать на примере».
2. По умолчанию работает локальная проверка. Включите «Проверить пунктуацию и орфографию онлайн», чтобы отправить текст в Яндекс.Спеллер и LanguageTool. При запуске через локальный сервис запросы идут к сервисам через локальный прокси; при открытии одного HTML-файла браузер обращается к API напрямую.
3. Прочитайте текст на проверке. Над списком замечаний есть номера для перехода к соответствующим местам. Контекстные запятые и другие предложения LanguageTool остаются на выбор редактора, даже если вариант только один. Локальные контекстные предложения тоже требуют выбора. Типографика и известные опечатки применяются автоматически.
4. При необходимости отредактируйте текст и нажмите «Повторно проверить». Кнопка «Подтвердить результат» доступна, даже если некоторые замечания остались; после подтверждения исправленный текст вернётся в поле на главном экране. Кнопка с двумя квадратами копирует чистый текст.

Код и URL защищены от исправлений и маскируются перед онлайн-проверкой. В локальном режиме онлайн-сервисы не вызываются. На результатах обновление и закрытие вкладки вызывают стандартное предупреждение браузера; текст и замечания сохраняются для восстановления. Браузер сам управляет отображением такого предупреждения.

## Качество и ограничения

После аудита словарные подсказки, включая единственный вариант, остаются на выбор редактора; «Крипис» не заменяется принудительно. Конец текста без точки может быть заголовком, поэтому точку тоже нужно подтвердить. Исключения для устойчивых сочетаний и защита технических фрагментов уменьшили ложные автоправки на составленном наборе. [Отчёт аудита](SAFETY_AUDIT.md) показывает сравнение до/после и оставшиеся проблемы. Новые примеры синтетические, с непроверенной редактором разметкой; независимая редакторская валидация по-прежнему нужна.

Проверка качества воспроизводится из `work/spell-build` командами `node test-app.mjs`, `node evaluate-corpus.mjs` и `node quality-gate.mjs`. 97 сценариев проходят на модульной и однофайловой версиях. В том числе тестируется защита корректных разговорных форм вроде «засрала» от ложной подсветки; дополнительные словарные исключения добавляются точечно после проверки контекста. В 30 публичных фрагментах локальные правила не меняли текст; проверка LanguageTool не предложила ни одной автозапятой в тех же 30 фрагментах. Все 8 намеренно внесённых ошибок обнаружены или отмечены, незамеченных ошибок в этом наборе — 0. Это небольшой регрессионный набор, частично использовавшийся при настройке, а не независимое измерение качества.

Набор проверок включает устойчивые выражения: они должны переживать коррекцию без смысловых изменений. Проверены правило «лучше поздно, чем никогда», согласование нескольких частых форм прошедшего времени с явным женским подлежащим и контекстная форма «в течение недели». Добавлены орфографические варианты имён и топонимов «Отчаянных домохозяек» из выбранной пользователем русской локализации. Они только исключаются из ложных орфографических замечаний и не нормализуются автоматически.

Редакторская выборка пока пуста. Для оценки пригодности к пилоту нужны обезличенные тексты с проверенным редактором результатом, разметка исходных ошибок и ложных срабатываний и регулярный прогон такого набора. `QUALITY_STATUS.json` показывает актуальную оценку. Продукт не гарантирует безошибочную корректуру; он помогает находить опечатки и возможные проблемы, а спорное оставляет на решение редактора.

Автоматическая редакторская перепись и перестройка смысла не включены: проверщик не должен придумывать факты или менять намерение автора. Для такой функции нужна отдельная генеративная модель и явное подтверждение переписанного текста. Сейчас проверка опирается на локальный словарь Hunspell, локальные контекстные правила, Яндекс.Спеллер и LanguageTool. Ни один из этих источников не гарантирует правильность всех слов и контекстных решений.

Воспроизводимый сценарий с намеренно испорченным текстом: `node deep-qa.mjs` из `work/spell-build`, без внешних запросов. Отчёт с исходником, автоматическим результатом и ручными предложениями находится в [DEEP_QA_REPORT.md](DEEP_QA_REPORT.md).

Свежие метрики, отложенная диагностика и оставшиеся пропуски — в [BROWSER_QUALITY_REPORT.md](BROWSER_QUALITY_REPORT.md). Для человеческой проверки подготовлена [форма редакторских эталонов](../../docs/editorial-review.html): карточки не одобрены заранее, JSON экспортируется только после явного выбора и подписи редактора. Данные источников и условия лицензии указаны в [TECHNICAL_CORPUS_LICENSE.md](../../work/spell-build/TECHNICAL_CORPUS_LICENSE.md).

Яндекс.Спеллер: [документация](https://yandex.ru/dev/speller/doc/ru/). LanguageTool: [HTTP API](https://dev.languagetool.org/public-http-api), [локальный сервер](https://dev.languagetool.org/http-server). Для использования публичного LanguageTool действуют его ограничения доступности и частоты запросов.
