# Локальный сервис «Типограф»

## Локальная нейросеть

На этом Mac установлен Ollama 0.40.4 (официальный архив `ollama-darwin.tgz`, SHA-256 `a4ceae4b2aaf18df37ebcbfb56ba3a37a87838631112d66c2be07268693c8d58`). Движок и модели находятся в игнорируемой папке `runtime`. Служебный ключ Ollama создаётся стандартно в `~/.ollama`; ключ не нужен приложению и не попадает в репозиторий.

1. Запустите **`start-neural.command`**.
2. Откройте **http://127.0.0.1:4173/**. Нейропроверка не работает в открытом отдельно HTML и на GitHub Pages.
3. Проверьте текст обычной кнопкой. На экране результата нажмите **«Проверить нейросетью»**.
4. Предложения появятся в общем списке замечаний с объяснением и номером. Применяйте их по одному или оставляйте исходный вариант.

Модель по умолчанию — [Qwen3 4B, Q4_K_M](https://ollama.com/library/qwen3:4b), около 2,5 ГБ загрузки. Первый запуск требует интернета для скачивания; сама нейропроверка выполняется на Mac через [Ollama `/api/chat`](https://docs.ollama.com/api/chat). Облачный режим отключён (`OLLAMA_NO_CLOUD=1`), сервер и Ollama слушают только `127.0.0.1`. Для конфиденциального текста оставьте **онлайн-переключатель выключенным**: он отдельно включает внешний Яндекс.Спеллер. Нейросетевая кнопка его не включает.

За один запуск принимается до 8 000 символов; текст разбивается на небольшие фрагменты. На Mac с 8 ГБ памяти проверка может занимать минуты. Есть отмена, тайм-аут, ограничение одного одновременного запуска и отбрасывание устаревшего ответа после изменения текста. При ошибке исходный результат остаётся доступен.

Модель возвращает JSON по схеме; сервер повторно проверяет цитаты и позиции. Предложения с выдуманным исходным фрагментом, неоднозначной привязкой, пересечением, изменением чисел или отдельных отрицаний, затрагиванием кода/URL/email/технических файлов отбрасываются. Пунктуационная правка не может менять слова; отдельные устойчивые сочетания защищены от известных лишних запятых. Если весь ответ отклонён из-за неверной цитаты или подмены слов при пунктуации, выполняется ровно одна попытка уточнения с той же валидацией. Это технические ограничения, а не доказательство сохранения любого смысла. Нейросеть может пропустить ошибку или предложить неверную правку; автоматического применения нет.

Остановка: `Ctrl+C` в окне запуска. Скрипт останавливает запущенный им Ollama; уже работавший чужой экземпляр не закрывает. Модель выгружается из памяти после двух минут без запросов. Чтобы использовать другую **локальную** модель, задайте `TYPOGRAF_AI_MODEL` при запуске; качество необходимо проверять отдельно.

Если Metal/GPU недоступен, остановите свой предыдущий запуск и выполните из этой папки `TYPOGRAF_AI_CPU=1 ./start-neural.command`. Этот режим полностью отключает выбор GPU и выгрузку KV-кэша в графическую память; он медленнее. При обычном запуске адаптер также пробует `num_gpu:0` после ошибки Metal, но некоторым версиям движка требуется именно полный перезапуск с указанной настройкой.

Для другого Mac загрузите официальный архив с [релиза Ollama](https://github.com/ollama/ollama/releases/tag/v0.40.4), проверьте указанную контрольную сумму, распакуйте в `runtime/ollama`, установите Node.js 20+ и укажите его через `TYPOGRAF_NODE`. Нужен macOS 14+ и достаточно памяти/места для выбранной модели. Многогигабайтные файлы не включены в Git и не могут быть частью одного HTML.

При наличии комплектного LanguageTool `start-neural.command` запускает и его с лимитом Java 512 МБ, чтобы сохранить прежнюю проверку. Отсутствие Java/LanguageTool не мешает работе нейросетевой кнопки.

Проверки: `node test-neural.mjs` (адаптер и HTTP-защита), `node test-neural-frontend.mjs` (предложения, применение, сбои, отмена и устаревшие ответы). Они используют тестовые ответы. Живую диагностику запускает `TYPOGRAF_AI_CPU=1 node smoke-neural.mjs`; она проверяет только фиксированные пользовательские примеры и синтетические контрольные фразы, не читает историю браузера. Отчёт — `outputs/typograf-prototype/NEURAL_SMOKE.json`; первоначальный ответ с обнаруженными дефектами сохранён в `NEURAL_SMOKE_BASELINE.json`. Эти несколько примеров не являются оценкой точности на произвольных статьях.

## LanguageTool и онлайн-проверка

На этом Mac запустите `start-local.command` и откройте `http://127.0.0.1:4173`. Скрипт запускает локальный LanguageTool, затем сервер приложения. Оба слушают только локальный компьютер. Чтобы остановить их, нажмите `Ctrl+C` в окне терминала.

В папке `runtime` лежат проверенные на этом Mac Java 21 и LanguageTool 6.9-SNAPSHOT. Java получена из [Eclipse Temurin](https://adoptium.net/temurin/releases/), LanguageTool — из [официальной инструкции по локальному серверу](https://dev.languagetool.org/http-server). Архивы загрузки после распаковки удалены. Для другого компьютера нужны совместимые Java 21, Node.js 20+ и локальный LanguageTool; пути в `start-local.command` потребуется изменить.

Сервер `server.mjs` отдаёт страницу и словарь, а запросы `/api/spelling` и `/api/grammar` направляет соответственно в Яндекс.Спеллер и локальный LanguageTool. Наш Node-сервис не записывает текст статьи в лог. Орфография при включённом онлайн-режиме всё ещё отправляется Яндексу. Для конфиденциальных текстов оставьте переключатель выключенным; полностью локальный орфографический сервис потребует отдельной замены Яндекс.Спеллера.

Открытый отдельно `file://.../index.html` остаётся учебной однофайловой версией: по включению переключателя он обращается к публичным API напрямую. Его не следует использовать как производственный сервер. Публичный API LanguageTool [запрещает автоматические запросы и не гарантирует доступность](https://dev.languagetool.org/public-http-api).

Проверка сервиса: `node test-service.mjs` и `node test-frontend-mode.mjs`. Можно использовать путь к Node.js, указанный в `start-local.command`, если команда `node` не найдена.
